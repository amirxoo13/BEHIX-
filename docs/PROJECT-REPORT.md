## ۰. خلاصه در یک پاراگراف

BEHIX یک **استودیوی ساخت انیمیشن آدمکی فارسی** است که تقریباً همه‌چیزش **داخل مرورگر کاربر** اجرا می‌شود. کاربر داستان را به فارسی ساده می‌نویسد («علی (مرد، سمت راست) وارد می‌شود و دست تکان می‌دهد.»). یک **تجزیه‌گر قاعده‌محور و بدون هوش مصنوعی** (`story-parse.ts`) متن را به صحنه، شخصیت، دیالوگ و کار تبدیل می‌کند. یک **کارگردان خودکار** (`story-direct.ts`) از آن خط زمانِ کلیددار می‌سازد: جای هر نفر، راه رفتن، نشستن، ژست، چهره، دوربین و زیرنویس. یک **موتور رسم قطعی** (`story-render.ts` + `animate.ts` + `figure.ts`) هر فریم را فقط از روی «زمان» روی Canvas می‌کشد. خروجی MP4 با WebCodecs و mediabunny (در Worker) یا با MediaRecorder ساخته می‌شود، به‌علاوهٔ SRT، متن صداپیشه، استوری‌بورد، کاور و JSON پروژه. صدای اختیاری دیالوگ با Gemini TTS از مسیر سرور `/api/tts` می‌آید. پروژه‌ها در IndexedDB مرورگر ذخیره می‌شوند. همان ویرایشگر با Capacitor به اپ اندروید آفلاین هم تبدیل می‌شود. کنار این مسیر اصلی، یک **مسیر قدیمی‌تر «عکس‌سر»** هم هست (`/photo`، `/scenario` … `/deliver`) با مدل داده، رندرر، صدا و خروجی جداگانه.

## ۴. مسیر اصلی: «داستان به فیلم» (پوشهٔ `src/studio/stick/`)

### ۴.۱ مدل داده: `project.ts`

**`StoryProject`** (طرح zod سخت‌گیر با `.strict()`، پس هر فیلد اضافه رد می‌شود):
```
{ schemaVersion: 1, id, title (≤120), text (≤20000),
  edits: StoryEdit[] (≤500), cast: {id,name,look}[] (≤8),
  settings: { format: portrait|square|landscape, fps: 30|60, captions, voices?: {castId: VoiceId} },
  updatedAt }
```
`superRefine` شناسهٔ تکراری در `cast` و `edits` را رد می‌کند.

**ایدهٔ کلیدی: متن منبع حقیقت است و ویرایش‌ها «وصله» هستند.**
پروژه حرکت یا فریم ذخیره نمی‌کند. فقط **متن** و فهرستی از **`StoryEdit`** را نگه می‌دارد. هر ویرایش یک تغییر کوچک روی یک «بخش» (beat) است: `x`، `face`، `duration`، `gesture`، `move`، `hold`، `sit`، `place`، `night`، `shot` و `fit`. فیلم هر بار از نو کامپایل می‌شود:

```
compileProject(p):
  plan = parseStory(p.text)
  ظاهر ذخیره‌شدهٔ cast روی plan.cast نوشته می‌شود
  edits = reconcileEdits(p.edits, plan)          ← دوباره پیدا کردن هدف هر ویرایش
  برای هر beat و هر edit حل‌شده: وصله روی beat/act/scene اعمال می‌شود
  return { ...directStory(plan), unresolved }
```

**پیدا کردن دوبارهٔ هدف ویرایش بعد از تغییر متن (`anchors` و `reconcileEdits`):**
- امضای هر beat این است: `JSON.stringify([سرصحنه, نوع, گوینده, متن نرمال‌شده])`.
- `anchor` شامل امضای خودِ beat و امضای beatهای قبلی و بعدی است.
- اگر امضا یکتا باشد، ویرایش به همان beat وصل می‌شود. اگر چند تطابق باشد، همسایه‌ها ابهام را حل می‌کنند. اگر باز هم یکتا نشد، `unresolved: true` می‌شود. ویرایش حل‌نشده حذف نمی‌شود؛ در رابط نشان داده می‌شود.
- اگر `actor` ویرایش دیگر در `plan.cast` نباشد، آن ویرایش هم unresolved می‌شود.

**`setEdit`** ویرایش موجودِ (همان beat و همان actor) را به‌روز می‌کند یا ویرایش تازه می‌سازد. دو قاعدهٔ مهم دارد:
1. **مکان و شب/روز مال کل صحنه است.** ویرایش جدیدِ place/night از هر beat، مقدار همان فیلد را از بقیهٔ ویرایش‌های همان صحنه پاک می‌کند (`project.ts:180-184`).
2. **`fit`:** اگر مدت را برنامه به اندازهٔ صدا گذاشته باشد، `fit=true` است. مدتی که کاربر دستی بگذارد `fit` را پاک می‌کند تا دیگر خودکار عوض نشود (`project.ts:173`).

**تاریخچه:** `History<T> = {past, present, future}` با سقف ۱۰۰ مرحله (`remember`، `undo`، `redo`).

**`copyCharacter`** کپی کامل (snapshot) می‌سازد. تغییر بعدی کتابخانهٔ شخصیت روی داستان‌های قبلی اثر ندارد.

### ۴.۲ فهم متن فارسی: `story-parse.ts` و `persian-rules.ts`

**بدون مدل زبانی و بدون اینترنت [قطعی].** همه با فهرست کلمه و regex انجام می‌شود. خروجی:
```
StoryPlan = { cast: StoryCastMember[], scenes: StoryScene[], warnings: string[] }
StoryScene = { heading, place: PlaceId, night, beats: Beat[] }
Beat = action{text, acts[]} | line{speaker, text, acts[]} | narration{text}
       + meta { id, source{line,start,end,text}, duration?, delay?, shot? }
Act  = { who, x?, sit?, gesture?, hold?, drop?, face?, move?, target?, thought? }
```

**پیش‌پردازش (`normalizeFa` در `catalog.ts`):** ی/ک عربی به فارسی، ۀ/ة به ه، أ/إ به ا، حذف اعراب، نیم‌فاصله به فاصله، رقم فارسی به لاتین، و نشانه‌گذاری به فاصله. همهٔ مقایسه‌ها روی این شکل نرمال انجام می‌شوند.

**جست‌وجوی فرهنگ لغت (`findAll`):** هر مدخل (`Entry`) یک `id` و چند مترادف دارد. مترادفِ دارای `*` «ریشه» است و صرف را هم پیدا می‌کند. تابع `stems()` به کلمه‌های بلندتر از ۳ حرف خودکار `*` می‌دهد.

**الگوریتم `parseStory`، به ترتیب اجرا:**
1. متن به ۲۰٬۰۰۰ نویسه بریده می‌شود و اگر بیشتر بود هشدار می‌دهد. سپس خط‌به‌خط می‌شود و خط‌های خالی حذف می‌شوند.
2. **دور ۱، شخصیت‌های صریح:** خط دیالوگ با الگوی `DIALOGUE = /^نام(?:\s*(ویژگی))?\s*:\s*متن$/` گوینده را می‌سازد. `cleanSpeaker` قید و فعل گفتن را حذف می‌کند («ناگهان علی گفت» ← «علی»). معرفی پرانتزی `DECL` هم شخصیت می‌سازد («مریم (زن، سمت چپ)»). `parseAttrs` از داخل پرانتز این‌ها را می‌خواند:
   - نوع: مرد، زن، پسر، دختر، پیرمرد، پیرزن، نوزاد؛ «بچه» و «پیر» نوع را اصلاح می‌کنند.
   - سمت: چپ، راست یا وسط. «چپ‌چپ» سمت حساب نمی‌شود.
   - لباس، عینک، سبیل، ریش، کلاه و مو.
3. **دور ۲، فاعل‌های آشنا:** در جمله‌های توصیفی، اسم‌های فهرست‌شده را تشخیص می‌دهد: ۵۳ اسم زنانه، ۵۳ اسم مردانه و نقش‌ها (پدربزرگ، دکتر، پلیس و …). شرط این است که اول جمله یا در زنجیرهٔ «X و Y» بیایند. اسم‌های دومعنایی (`AMBIGUOUS`: ستاره، سحر، رها، شیرین، غزل، مهتاب، امید) فقط از دیالوگ یا پرانتز شخصیت می‌شوند.
4. **دور ۳:** «به طرف/به سمت/کنار + اسم آشنا» هم شخصیت می‌سازد.
5. **ساخت صحنه و beat:**
   - `isHeading` سرصحنه را تشخیص می‌دهد: خطی که با صحنه، سکانس، پلان، مکان یا لوکیشن شروع شود، یا خط کوتاهِ ≤۷ کلمه که اسم مکان دارد ولی فعل یا شخصیت ندارد.
   - مکان: بلندترین مترادف برنده است («اتاق کار» بر «اتاق»). شب/روز از کلمه‌های `NIGHT` و `DAY` خوانده می‌شود. صحنهٔ بی‌مکان مکان صحنهٔ قبل را ارث می‌برد. اولین جملهٔ توصیفیِ دارای اسم مکان هم می‌تواند مکان صحنه را تعیین کند.
   - دیالوگ beat از نوع `line` می‌شود. پرانتزهای داخل جمله «دستور بازی» گوینده‌اند و با `actsFor(dir, speaker)` خوانده می‌شوند. گویندهٔ ناشناخته یا «راوی» beat از نوع `narration` می‌سازد که فقط زیرنویس است.
   - جملهٔ توصیفی: `sentences()` آن را جمله‌جمله می‌کند و `actionClauses()` در «و، سپس، بعد، ،، ؛» به بندها می‌شکند. شکستن فقط وقتی انجام می‌شود که بخش قبلی فعل داشته باشد. هر بند یک beat از نوع `action` است.
   - `readDelay`: «بعد از/پس از N ثانیه» در beat فیلد `delay` می‌گذارد. «چند» برابر ۳ است و سقف ۶۰ ثانیه است.
   - ضمیر «او/اون» فقط وقتی جایگزین می‌شود که فاعل قبلی **دقیقاً یک نفر** باشد؛ وگرنه هشدار می‌دهد.
   - بند بدون فاعل صریح، فاعل بند قبلی همان جمله (`chainSubjects`) را ارث می‌برد.
6. **`actsFor(text, speaker)`، قلب فهم کار:**
   - اگر فعل منفی باشد (`hasNegativeVerb`: نمی…، نکرد…، نرفت… و غیره)، هیچ کاری برنمی‌گرداند.
   - `conjugations` صرف‌های فعل را یکسان می‌کند («می‌نشینند» ← «می نشیند»، «رفتند» ← «رفت»). ریشه‌ها صریح فهرست شده‌اند و کلمهٔ ناشناخته هرگز با حذف دلبخواهی پسوند ریشه‌یابی نمی‌شود.
   - فاعل‌ها: اولین اسم و اسم‌هایی که فقط «و» بینشان است.
   - حرکت (`move`) با این اولویت انتخاب می‌شود: ورود (ENTER) > نزدیک‌شدن (APPROACH با مفعول) > به چپ/راست/وسط > خروج (EXIT). عبارت‌های `NOT_EXIT` مثل «راه می‌رود» و «یادش رفت» خروج نیستند.
   - نشستن و ایستادن.
   - ژست (۱۹ نوع)، شیء دستی (۱۲ نوع) و چهره (۲۱ نوع): هرکدام به **نزدیک‌ترین فاعلِ قبل از خودش** نسبت داده می‌شود (`owner()`). اگر بعد از همهٔ فاعل‌ها بیاید، مال همه است.
   - قواعد جانبی: ژست تلفن یعنی شیء دستی گوشی؛ رانندگی یعنی نشسته؛ فکر کردن یعنی حباب فکر و چهرهٔ «فکر».
7. **شناسهٔ پایدار beat:** `textId("سرصحنه|نوع|گوینده|متن")` (هش FNV-1a در `persian-rules.ts:textId`) به‌اضافهٔ شمارندهٔ تکرار. پس beatهای یکسان در یک صحنه شناسهٔ متفاوت می‌گیرند.
8. **هشدارها:** جملهٔ نافهمیده (با شمارهٔ خط و نمونهٔ دستور)، مرجع مبهم ضمیر، مکان ناشناخته، جنسیت حدسی («مرد در نظر گرفته شد»)، بیش از ۸ شخصیت، و نبود هیچ شخصیت.

### ۴.۳ کارگردان خودکار: `story-direct.ts`

ورودی `StoryPlan` است و خروجی `Directed = { timeline, cues, warnings, beats: BeatTiming[] }`.

**برای هر صحنه:**
1. **حاضران:** افراد به ترتیب اولین ذکر می‌آیند و حداکثر `MAX_ON_STAGE = 5` نفر می‌مانند. اضافه‌ها حذف می‌شوند و هشدار می‌دهند (`story-direct.ts:22,194`).
2. **چیدمان چپ به راست:** ترتیب «سمت چپ»، بی‌سمت، «سمت راست» است. در مکان `forceSit` (ماشین) راننده راست قاب می‌نشیند. جای ایستادن از `spread(n)` می‌آید: یک نفر `[0.5]`، دو نفر `[0.3,0.7]`، سه نفر `[0.22,0.5,0.78]` و …
3. **صندلی‌ها:** `place.seats` فهرست xهای نشیمن است. `nearestSeat` و `takeSeat` نشیمن را به هر نفر اختصاص می‌دهند. مکان بدون صندلی هشدار می‌دهد و همه ایستاده می‌مانند.
4. **حالت اولیه:** کسی که بعداً «وارد می‌شود» بیرون قاب شروع می‌کند (x برابر `-0.16` یا `1.16`).
5. **حلقهٔ beatها** (ساعت محلی صحنه از `t = 0.5` شروع می‌شود):
   - `delay` به `t` اضافه می‌شود. beat فقط‌مکث (delay بدون act) فقط زمان را جلو می‌برد.
   - مدت پیش‌فرض: دیالوگ `lineDuration(text)` است. برای action، اگر کاری داشته باشد ۱٫۵ ثانیه وگرنه ۰٫۷ ثانیه. روایت هم `lineDuration`.
   - **`lineDuration = max(1.4, 0.45 + کلمه/2.4 + 0.18×(، ؛ :) + 0.3×(. ! ؟ …))`**. سرعت فرضی ۲٫۴ کلمه در ثانیه است. این **تخمین** است و تلفظ را نمی‌شناسد.
   - هر act به ترتیب اعمال می‌شود: x، چهره، رها کردن یا گرفتن شیء، حرکت. `walkTo` اول بلند می‌کند (۰٫۵ ثانیه) و بعد راه می‌برد؛ زمان راه رفتن `max(0.7, |dx|×2.6)` است. ورود کنار هدف ±۰٫۲ می‌ایستد. بعد نشستن/ایستادن و ژست می‌آید. از روی این‌ها `ActorKey` با `poseFor(sit, gesture, hold, face, toRight)` ساخته می‌شود (نگاشت به ۳۵ ژست آماده).
   - **دیالوگ:** بازهٔ حرف زدن `from..to` بعد از پایان حرکت‌ها شروع می‌شود و `speechPulses` پالس‌های دهان را می‌سازد. اگر دیالوگ ≥۷ کلمه باشد و گوینده ژست یا شیء نداشته باشد، با احتمال قطعیِ hash یک ژست «توضیح دادن» موقت می‌گیرد. دوربین در دیالوگ عادی تا ۱٫۰۷ به سمت گوینده جلو می‌رود و در «شوک/تعجب/فریاد/ترس» (`PUNCH`) تا ۱٫۲۸ زوم ناگهانی می‌کند.
   - **نمای دستی کاربر (`beat.shot`)** روی نمای خودکار نوشته می‌شود: باز = ۱، متوسط = ۱٫۱۸، نزدیک = ۱٫۵ (`SHOT_ZOOM`).
   - **بازگشت:** ژست‌های لحظه‌ای (`MOMENTARY`: اشاره، دست تکان دادن، شادی، پرش …) بعد از `min(dur-0.05, max(1.1, 0.6·dur))` برمی‌گردند. چهره‌های شدید با جدول `CALM` در پایان beat آرام می‌شوند (خنده ← لبخند، شوک ← تعجب ← خنثی …).
6. پایان صحنه `t + 0.8` است و صحنهٔ بعدی از `clock` ادامه می‌دهد.

**`cues` و SRT:** هر دیالوگ یک `Cue` با زمان مطلق، گوینده، متن و حالت است. `cuesToSrt` آن را به SRT با پیشوند حالت فارسی تبدیل می‌کند («سارا (عصبانی): …»).

### ۴.۴ موتور حرکت: `animate.ts`، `speech.ts`، `poses.ts`، `face.ts`

**`actorAt(track, t, lookAt)`** وضعیت آدمک را در لحظهٔ t برمی‌گرداند:
- `activeKey` کلید فعال را پیدا می‌کند.
- **راه رفتن:** اگر x کلید با کلید قبل فرق کند، x با منحنی smoothstep درون‌یابی می‌شود. `walkPose` چرخهٔ پا و دست می‌سازد (۱٫۹ گام در ثانیه) و بدن کمی بالا و پایین می‌رود.
- **حرکت هم‌پوشان (`layered`):** بدن تأخیر صفر دارد، بالای بازو ۰٫۰۴، سر ۰٫۰۷ و ساعد ۰٫۰۹ با فنر. در نتیجه بدن اول حرکت می‌کند و دست و سر کمی دیرتر.
- **`springEase`** فنر میرای بسته است: `1 - e^{-7x}(cos10x + 0.7 sin10x)`، نرمال‌شده روی [۰،۱]، با سرعت صفر در دو سر بازه.
- **پیش‌حرکت:** پیش از ژست پرش، شوت یا شادی، ۰٫۲ ثانیه خم شدن اضافه می‌شود. این از کلید بعدی خوانده می‌شود، نه از تاریخچهٔ پخش.
- **زنده بودن:** نفس، جابه‌جایی وزن و تکان سر با سینوس‌هایی که seed هر شخصیت را دارند.
- **نگاه:** شنونده به گوینده نگاه می‌کند. سر هنگام حرف زدن تکان می‌خورد.
- **چهره:** `mixFace` در ۰٫۳ ثانیه از حالت قبلی به حالت تازه می‌رود (۲۱ حالت پارامتری در `face.ts`).
- **پلک:** دورهٔ نامنظم ولی قطعی `2.4 + hash(seed)×1.6` ثانیه.
- **دهان:** `talkAmount` از پالس‌ها (`mouthAt`، سینوس در بازهٔ هر هجا) یا در نبود پالس از الگوی hash با حدود ۷ هجا در ثانیه.

**`speech.ts`:** `estimateSyllables` یک واژه‌نامهٔ کوچک ۲۵ کلمه‌ای دارد. برای بقیه `max(تعداد ا/آ/و/ی, ceil(طول/3))` را می‌گیرد و به ۱ تا ۸ محدود می‌کند. `speechPulses` بازهٔ حرف را بین هجاها و مکث‌ها تقسیم می‌کند: مکث بین کلمه ۰٫۳۵، ویرگول ۰٫۹ و نقطه ۱٫۸ واحد.

8. **میکس:** `mixClips` همهٔ کلیپ‌ها را در یک کانال ۲۴ کیلوهرتزی جمع و برش (clip) می‌کند. در پیش‌نمایش، `Player` هر کلیپ را با `AudioBufferSourceNode` از همان لحظهٔ پخش اجرا می‌کند.

### ۴.۸ فضای کار و ذخیره‌سازی: `use-workspace.ts` + `project-db.ts`

- **IndexedDB `behix-story-projects` نسخهٔ ۲:**
  - `projects` با کلید `id`
  - `characters` (کتابخانهٔ مشترک شخصیت‌ها)
  - `exports` (خروجی‌های صف و کلیپ‌های صدا)
  - `meta` (علامت مهاجرت `legacy-v1`)
- **`openProjects`:** هر تراکنش اتصال را باز و بعد می‌بندد. `onversionchange` اتصال را می‌بندد. اگر رویداد `onblocked` بیاید (تب دیگری نسخهٔ قدیمی را باز نگه داشته)، خطای فارسی می‌دهد.
- **`saveProject`:** پیش از نوشتن، پروژه را `importProject(projectJson(p))` می‌کند، یعنی با zod دوباره اعتبارسنجی می‌کند. پس دادهٔ نامعتبر هرگز نوشته نمی‌شود.
- **`migrateLegacy`:** در **یک تراکنش** روی `projects` و `meta`. اگر علامت `legacy-v1` نباشد، متن `localStorage["behix-story-v1"]` را پروژهٔ «داستان نخست» می‌کند و علامت را می‌گذارد. اگر متن قدیمی خالی باشد و پروژه‌ای از قبل باشد، پروژهٔ خالی اضافه نمی‌سازد. localStorage پاک نمی‌شود.
- **`useStoryWorkspace(sample, requestedId)`:**
  - **ذخیرهٔ خودکار** با هر تغییر `project` انجام می‌شود. نوشتن‌ها در یک صف Promise پشت هم قرار می‌گیرند و شمارهٔ ترتیب (`latest`) جلوی پیام قدیمی را می‌گیرد.
  - **`commit(change, group)`:**
    - `group=true`: تایپ با فاصلهٔ کمتر از ۷۰۰ میلی‌ثانیه یک مرحلهٔ واگرد حساب می‌شود.
    - `"silent"`: اصلاح خودکار بدون مرحلهٔ واگرد.
    - `revision` با هر تغییر یکی زیاد می‌شود.
  - **`flush()`:** آخرین نسخه را پشت صف ذخیره می‌کند و فقط وقتی `true` برمی‌گرداند که در این فاصله ویرایش تازه‌ای نیامده باشد. هم `useBlocker` در `/story` و هم دکمهٔ برگشت در اندروید به آن تکیه می‌کنند.
  - **`open(p)`:** اول flush می‌کند و بعد تاریخچهٔ تازه می‌سازد. قفل `switching` جلوی کلیک دوتایی را می‌گیرد.
  - **`remove()`:** اول flush، بعد حذف، بعد باز کردن اولین پروژهٔ باقی‌مانده یا ساخت پروژهٔ تازه.

## ۵. مسیر دوم: «عکس‌سر» (پوشهٔ `src/studio/` + `components/*` + هفت route)

این مسیر قدیمی‌تر است و **از مسیر داستان کاملاً جداست**: مدل داده، رندرر، ذخیره‌سازی، صدا و خروجی هرکدام جدا هستند.

- **مدل (`types.ts`):** پروژه آرایه‌ای از `Shot` (نما) است. هر نما سرصحنه، شرح، دیالوگ، گوینده (a، b یا none)، مدت، پس‌زمینه (۱۷ `BgId` از جمله برج میلاد، میدان آزادی، سعادت‌آباد و خیابان فرشته) و ۳ طرح برای هر مکان دارد. همچنین شب، عدسی (۶ `CameraId`)، دو بازیگر اصلی `actorA/B` (شخصیت، حس از ۷ `Emotion`، حرکت از ۶ `Action`، x و scale)، حداکثر ۳ بازیگر اضافه، اشیاء جدا (`props`)، افکت صوتی (۹ `SfxId`) و زیروبم.
- **شخصیت‌ها (`characters.ts`):** شخصیت‌های آماده (`CAST`) و حداکثر ۸ شخصیت سفارشی که **سرشان از عکس** است (`HeadImage`: data URL شفاف، جای دهان و چشم، رنگ پوست کنار دهان).
- **ساخت شخصیت از عکس (`character-maker.tsx`):**
  - حذف پس‌زمینهٔ یک‌رنگ (`removeFlatBackground`، تلورانس ۴۲).
  - بریدن به محتوا (`contentBox`).
  - تشخیص خودکار دهان و چشم با MediaPipe (`face-detect.ts`، بارگذاری تنبل از `/mediapipe/*` همین سایت). اگر تشخیص نشد، کاربر با کلیک تعیین می‌کند.
  - نمونه‌برداری رنگ پوست (`sampleSkin`).
- **حالت (`store.ts`، zustand):**
  - `boot()` پروژه را از IndexedDB `behix`، مخزن `kv`، کلید `project` می‌خواند.
  - ذخیره‌ها در یک صف (`saveChain`) پشت هم قرار می‌گیرند. تا پایان boot هیچ نوشتنی انجام نمی‌شود. اگر یک ذخیره شکست بخورد، ذخیرهٔ خودکار قفل می‌شود (`storageLocked`).
- **ماندگاری (`persist.ts`، ۵۸۰ خط) با تدافع زیاد:**
  - هر دو منبع (IndexedDB و localStorage `behix-project-v1`) خوانده می‌شوند و نسخهٔ معتبرِ جدیدتر (`savedAt`) انتخاب می‌شود.
  - دادهٔ خراب یا نماهای نامعتبر، پیش از هر بازنویسی، با پیشوند `corrupt-` قرنطینه (کپی) می‌شوند.
  - localStorage فقط بعد از نوشتن و بازخوانی موفق IndexedDB پاک می‌شود.
  - پشتیبان JSON با قالب `behix-backup` نسخهٔ ۱ و سقف ۵ مگابایت است.
- **رسم (`frame.ts`، `draw-actor.ts`، `draw-bg.ts`، `bg-*.ts`، `rig.ts`، `props.ts`):** رندرر رنگی جدا با سر نقاشی‌شده یا سر عکسی. IK دواستخوانی (`solve2`)، چرخهٔ راه رفتن، viseme از حروف (`visemeFromChar`: آ/ع/ح/خ ← ah، س/ش/ز ← ee، و ← oo، ب/پ/ف/م ← fv)، پس‌زمینهٔ متحرک برای مکان‌های بیرونی و اشک قطعی (`tears.ts`).
- **صدا (`audio.ts`، `lipsync.ts`، `tts.ts`):**
  - ضبط میکروفون با MediaRecorder؛ URL صدا فقط در حافظهٔ همان نشست است (blob URL) و با بستن صفحه پاک می‌شود.
  - ۹ افکت صوتی که با WebAudio **سنتز** می‌شوند.
  - میکس آفلاین (`renderMixOffline`).
  - دهان از انرژی و ZCR صدای ضبط‌شده (`buildMouthTrack`).
  - **TTS داخل مرورگر با Piper** (صداهای `fa_IR-amir-medium` و `fa_IR-gyro-medium`). بار اول حدود ۶۳ مگابایت از Hugging Face دانلود و در OPFS نگه داشته می‌شود.
- **چیدن خودکار سناریو (`auto-script.tsx` → `auto-layout.ts`):** سه روش «هوشمند»، «دیکشنری» و «مدل».
  - دیکشنری: `script-plan.ts:planFromDictionary`.
  - روش «هوشمند» اگر دیکشنری همه‌چیز را فهمیده باشد، مدل را صدا نمی‌زند (۰ توکن).
  - مدل: server function `understandScript` در `lib/script-ai.ts` با `SCRIPT_AI_BASE_URL/API_KEY/MODEL`. `temperature=0`، timeout ۶۰ ثانیه، سقف IP در ساعت و سقف توکن روزانه. جواب با `planFromModelReply` اعتبارسنجی می‌شود.
  - کش ۲۰ جواب آخر در حافظهٔ مرورگر.
- **خروجی (`export-film.ts`):** با WebCodecs، MP4 در ۳۰ فریم با H.264 چهار مگابیتی و AAC چهل‌وهشت کیلوهرتزی (میکس آفلاین) ساخته می‌شود. fallback: MediaRecorder روی بوم زنده و پخش واقعی با `setPlaying`. اگر پروژه هنگام ساخت عوض شود (`exportSnapChanged`)، فایل دور ریخته می‌شود. صفحهٔ `/deliver` فایل را دانلود یا با Web Share اشتراک می‌گذارد.

## ۶. سرور (فقط سه کار واقعی دارد)

### ۶.۱ `POST /api/tts` (`src/routes/api/tts.ts`)
1. اگر `GOOGLE_CLOUD_PROJECT` نباشد، پاسخ ۵۰۳ «سرویس صدا روی این سرور فعال نیست» برمی‌گرداند.
2. بدنه با zod `.strict()` بررسی می‌شود: `text` بین ۱ و ۴۰۰ نویسه، `voice` یکی از ۳۰ صدا، `prompt` حداکثر ۳۰۰ نویسه.
3. کلید `tts/<sha256>.mp3` ساخته می‌شود. **اول کش باکت** خوانده می‌شود؛ در صورت موفقیت پاسخ با هدر `x-cache: hit` برمی‌گردد (کش قبل از سقف‌ها بررسی می‌شود، پس درخواست کش‌شده سهمیه مصرف نمی‌کند).
4. سقف IP: ۱۲۰ درخواست در ۱۰ دقیقه برای هر IP (`TTS_PER_IP`). IP با `clientIp` از `lib/rate-limit.ts` به دست می‌آید.
5. سقف روزانه (`TTS_PER_DAY`، پیش‌فرض ۳۰۰۰) با `reserveDaily` در `lib/tts-quota.ts`:
   - با باکت: شمارنده در metadata شیء `quota/<YYYY-MM-DD>` ذخیره می‌شود و با `ifMetagenerationMatch` به‌روز می‌شود (قفل خوش‌بینانه). در برخورد هم‌زمان حداکثر ۸ بار با فاصلهٔ تصادفی دوباره تلاش می‌کند.
   - بی‌باکت: شمارندهٔ حافظهٔ همان نمونهٔ سرور.
   - اگر ساخت شکست بخورد، سهم به **همان روزِ رزرو** پس داده می‌شود.
6. توکن از metadata server گوگل گرفته می‌شود (`tts.ts:26`). بعد درخواست به `texttospeech.googleapis.com/v1/text:synthesize` با `modelName: gemini-2.5-pro-tts`، `languageCode: fa-IR` و خروجی MP3 در ۲۴ کیلوهرتز می‌رود.
7. MP3 در باکت ذخیره می‌شود و پاسخ با `cache-control: private, max-age=31536000, immutable` برمی‌گردد.
8. CORS فقط برای مبدأهای `capacitor://localhost`، `https://localhost` و `http://localhost` (اپ اندروید) باز است.

### ۶.۲ `understandScript` (`src/lib/script-ai.ts`)
server function با `createServerFn`. ورودی بررسی می‌شود: سناریو حداکثر ۱۲٬۰۰۰ نویسه، cast حداکثر ۸ مورد با شناسهٔ `^u-[a-z0-9]{3,24}$`. نرخ با `createLimiter` محدود می‌شود. کلید API هرگز به مرورگر نمی‌رسد.

### ۶.۳ شناسایی IP (`src/lib/rate-limit.ts:73-89`)
- روی Vercel: `x-vercel-forwarded-for`.
- روی سرور خودتان: فقط هدری که نامش در `TRUSTED_IP_HEADER` آمده باشد. برای `x-forwarded-for` **آخرین** مقدار خوانده می‌شود.
- در غیر این دو حالت: آدرس سوکت.

Dockerfile مقدار `TRUSTED_IP_HEADER=x-forwarded-for` را می‌گذارد. راهنمای nginx در `docs/self-host.md` است.

## ۱۳. قراردادها و ثابت‌هایی که هر تغییر باید حفظ کند

1. **فریم = f(زمان، داده، seed).** هرگز `Math.random()` یا وابستگی به فریم قبلی در مسیر رندر وارد نکنید. برای «تصادف» از `hash()` استفاده کنید.
2. **`projectSchema` سخت‌گیر است (`.strict()`).** هر فیلد تازه باید **اختیاری** اضافه شود تا JSONها و IndexedDBهای قدیمی معتبر بمانند. `schemaVersion` فعلاً `1` است.
3. **شناسهٔ beat از متن ساخته می‌شود.** تغییر `normalizeFa`، `textId` یا ساختار امضا همهٔ ویرایش‌های ذخیره‌شده را unresolved می‌کند.
4. **کلید کلیپ صدا** `SHA-256(TTS_MODEL|voice|prompt|text)` است و در مرورگر و سرور یکی است. عوض کردن `TTS_MODEL` یا متن `stylePrompt` همهٔ کش را باطل می‌کند و دوباره هزینه می‌برد.
5. **ذخیره فقط از راه `saveProject`** (اعتبارسنجی پیش از نوشتن) و فقط پشت صف `use-workspace`.
6. **پیش از ترک ویرایشگر `flush()`.**
7. **فایل‌های سکو** (بخش ۱۰) نباید حذف شوند (`AGENTS.md`). `startup.sh`، `public/__grok/` و `PreviewHostBridge` هم قرارداد سکو هستند.
8. **فرض‌های نرخ:** هر مسیر سرور تازه که هزینه دارد باید `clientIp()` و سقف داشته باشد.
9. **تست‌ها با `node --experimental-strip-types`** اجرا می‌شوند. پس importهای نسبی داخل `src/studio/**` پسوند `.ts` دارند، مثل `import … from "./project.ts"`. مسیر `@/` فقط در فایل‌های React و Vite مجاز است.

## ۱۵. واژه‌نامه

- **beat (بخش):** کوچک‌ترین واحد داستان؛ یک دیالوگ، یک بند توصیفی یا یک روایت.
- **Act:** کار یک شخصیت در یک beat (حرکت، ژست، چهره، شیء، نشستن).
- **StoryEdit:** وصلهٔ کاربر روی یک beat، با لنگر (anchor) برای پیدا شدن دوباره.
- **anchor و signature:** امضای متنی beat و همسایه‌هایش.
- **Directed:** خروجی کارگردان: `timeline` (صحنه‌ها، کلیدهای بازیگر، دوربین، زیرنویس)، `cues` (دیالوگ‌ها برای SRT) و `beats` (زمان هر بخش).
- **ActorKey:** کلید زمانی بازیگر (ژست، چهره، x، شیء، مدت ترکیب، مدت راه رفتن).
- **pulse:** بازهٔ باز شدن دهان برای یک هجا.
- **fit:** مدت دیالوگ را برنامه به اندازهٔ صدای واقعی گذاشته است.
- **مسیر عکس‌سر:** خط تولید قدیمی‌تر نما‌به‌نما با سر از عکس واقعی (`/photo` و هفت مرحله).
