# ابزار داستان BEHIX

مسیر محصول `/story` است. متن فارسی با فرهنگ لغت و قواعد صریح به حرکت تبدیل می‌شود؛ این مسیر مدل یا API هوش مصنوعی ندارد. فیلم بی‌صداست و صداپیشه از SRT و برگهٔ دیالوگ استفاده می‌کند.

## رندر و حرکت

- `src/studio/stick/ink.ts`: خطوط اندام با perfect-freehand و فشار تعریف‌شده در طول مسیر؛ خروجی به سرعت حرکت اشاره‌گر وابسته نیست.
- `holds.ts`: محل گرفتن، محدودهٔ اشیا و حل هندسی دو استخوان بازو. تماس گوشی و خوراکی با صورت عمدی است؛ ماتریس رندر به‌تنهایی اثبات نبود تمام برخوردهای بصری نیست.
- `speech.ts` و `animate.ts`: فنر میرا با فرمول بسته، پیش‌حرکت، راه‌رفتن و پالس دهان از متن. تعداد هجا **تخمینی** است: واژه‌نامهٔ محدود و قاعدهٔ طول/حروف جای تلفظ واقعی را نمی‌گیرد. نشانه‌گذاری مکث ایجاد می‌کند.
- فریم از زمان، دادهٔ داستان، seed و تنظیمات تولید می‌شود. `hash`/`rng` جای تصادف هنگام رسم را می‌گیرند. شناسه‌های تصادفی پروژه در رندر دخالت ندارند. یکسانی پیکسل برای مرورگر، فونت و دارایی‌های یکسان سنجیده می‌شود، نه میان همهٔ مرورگرها یا بایت‌های فایل ویدیو.
- `places-extra.ts`: بیمارستان، مغازه، آسانسور، مترو، اتوبوس، پشت‌بام، حیاط و عروسی. کنترل، بشقاب، کیسهٔ خرید، چتر و لپ‌تاپ در `holds.ts`؛ نوزاد و لباس‌ها در `figure.ts`.

## نوشتن و ویرایش داستان

```text
صحنه: حیاط
علی (مرد، پیراهن) و سارا (زن) وارد می‌شوند و دست تکان می‌دهند.
علی: سلام، امروز آماده‌ای؟
پس از ۲٫۵ ثانیه
سارا می‌خندد. او دست تکان می‌دهد.
```

`persian-rules.ts` صرف‌های پشتیبانی‌شده، فعل منفی، بندهای متوالی و مکث را تعریف می‌کند. «بعد از چند ثانیه» سه ثانیه است. «او/اون» فقط به آخرین فاعل صریحِ یکتا در همان صحنه برمی‌گردد؛ ابهام هشدار دارد. جملهٔ ناشناخته با متن اصلی، شمارهٔ خط و نمونهٔ دستور نشان داده می‌شود. سقف متن ۲۰٬۰۰۰ نویسه و سقف شخصیت هشت است.

در خط زمان بخش را انتخاب کنید؛ مدت دیالوگ، حالت چهره و جای افقی شخصیت قابل تغییر است. کشیدن شخصیت روی بوم هم جای آن را تغییر می‌دهد. مدت تازه، زمان‌های بعدی، دهان و SRT را دوباره محاسبه می‌کند.

## پروژه و ذخیره‌سازی

- JSON پروژه `schemaVersion: 1` دارد؛ `project.ts` با zod ساختار، نسخه، شناسه‌های تکراری، اعداد و محدوده‌ها را بررسی می‌کند. ورود JSON معتبر پروژهٔ جدا می‌سازد؛ فایل نامعتبر جای پروژهٔ باز را نمی‌گیرد.
- IndexedDB با نام `behix-story-projects` و نسخهٔ ۲، مخزن‌های `projects`، `characters`، `exports` و `meta` دارد. پروژه و علامت مهاجرت متن `behix-story-v1` در یک تراکنش نوشته می‌شوند؛ متن localStorage حذف نمی‌شود.
- ذخیره در همین مرورگر است. پاک‌شدن دادهٔ سایت یا کمبود سهمیه می‌تواند ذخیره را از بین ببرد/متوقف کند؛ JSON راه نسخهٔ پشتیبان است. خطای ذخیره در رابط نمایش داده می‌شود.
- پس از تغییر متن، ویرایش‌ها بر اساس صحنه، نوع بخش، گوینده، متن نرمال‌شده و همسایه‌ها تطبیق داده می‌شوند. هدف حذف‌شده یا مبهم به‌عنوان ویرایش حل‌نشده حفظ می‌شود؛ در رابط می‌توان آن را به بخش انتخاب‌شده وصل یا حذف کرد.
- undo/redo در نشست جاری تا ۱۰۰ تغییر نگه داشته می‌شود. تایپ با فاصلهٔ کمتر از ۷۰۰ میلی‌ثانیه یک گروه است؛ هر کشیدن یک تغییر. بازکردن پروژه تاریخچهٔ همان نشست را از نو آغاز می‌کند.
- کتابخانهٔ شخصیت میان داستان‌ها مشترک است؛ هر داستان یک کپی از ظاهر انتخاب‌شده می‌گیرد. تغییر کتابخانه ظاهر داستان‌های قبلی را عوض نمی‌کند.

## خروجی

`layout.ts` سه قاب ۱۰۸۰×۱۹۲۰، ۱۰۸۰×۱۰۸۰ و ۱۹۲۰×۱۰۸۰ را تعریف می‌کند. قالب‌های `templates.ts` فقط برای سنجش تصویر در اسکریپت بررسی هستند و در رابط نشان داده نمی‌شوند. پروژهٔ تازه متن خالی دارد.

`story-export.worker.ts` در صورت پشتیبانی از OffscreenCanvas و رمزگذار لازم، MP4 را با WebCodecs/mediabunny تولید می‌کند. زمان هر فریم `frameIndex / fps` است. فونت صفحه و Worker از فایل‌های یکسان بارگذاری می‌شود. پیام‌ها شناسه دارند و لغو Worker را متوقف می‌کند. اگر Worker قابل استفاده نباشد، رمزگذاری در صفحه امتحان می‌شود؛ بدون رمزگذار مناسب، MediaRecorder بوم را در زمان واقعی ضبط می‌کند.

نوع فایل MediaRecorder از MIME پشتیبانی‌شدهٔ مرورگر انتخاب می‌شود. **MP4 الزاماً به معنی H.264 نیست.** ضبط زنده ممکن است افت فریم/اختلاف زمان داشته باشد؛ پنهان‌شدن صفحه ضبط را با پیام فارسی متوقف می‌کند. پاک‌سازی stream، animation frame، listener و بوم در پایان/لغو انجام می‌شود.

صف دسته‌ای داستان‌ها را به ترتیب انتخاب پردازش می‌کند و فیلم، SRT، TXT صداپیشه و PNG واقعی را در IndexedDB نگه می‌دارد. خطای یک قسمت وضعیت همان قسمت را نشان می‌دهد؛ قسمت بعدی ادامه می‌یابد. دکمهٔ لغو بقیهٔ صف را لغو می‌کند. خروجی‌های ذخیره‌شده را می‌توان از رابط دریافت یا پاک کرد. thumbnail از وسط نخستین دیالوگ یا نخستین صحنهٔ بدون دیالوگ ساخته می‌شود.

پیش‌نمایش زمان رابط را حداکثر ۱۰ بار در ثانیه به React می‌دهد. صدک ۹۵ هزینهٔ رسم در پنجره‌های نمونه محاسبه می‌شود؛ عبور از ۱۶٫۷ms وضوح پیش‌نمایش را کاهش می‌دهد. این کار ابعاد فایل خروجی را تغییر نمی‌دهد و تضمین ۶۰fps روی همهٔ دستگاه‌ها نیست.

منابع مرورگر: [OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas)، [WebCodecs](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API)، [MediaRecorder.isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)، [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API).

## اجرای آزمون‌ها

از ریشهٔ مخزن، با وابستگی‌های lockfile و Node پشتیبان `--experimental-strip-types`:

```bash
node --experimental-strip-types --test src/studio/stick/*.test.ts
npm run typecheck
npm run lint
node scripts/run-tests.mjs
env -u DATABASE_URL npm run build
```

حذف `DATABASE_URL` از محیط **همین فرمان build** مانع migration به دیتابیس مشترک در این بررسی می‌شود؛ فایل تنظیمات یا رمزها تغییر نمی‌کنند.

آزمون‌های مرورگر به dev آماده با `env -u DATABASE_URL npm run dev` و مرورگر مشترک Preview وصل می‌شوند. بیرون از این محیط، `BROWSER_CDP_URL` باید به Chromium سازگار و در حال اجرا اشاره کند. این آزمون‌ها پروژه‌های موقت خود را می‌سازند و روی دادهٔ کاری نباید هم‌زمان ویرایش انجام شود.

```bash
node scripts/story-browser.mjs
node scripts/story-matrix.mjs
node scripts/story-export-check.mjs
node scripts/story-tools-check.mjs
node scripts/story-failure-check.mjs
node scripts/story-soak.mjs
```

آزمون‌ها را برای سنجش زمان و ضبط، **پشت سر هم** اجرا کنید. soak پخش واقعی ۶۰۰ ثانیه است؛ در طول آن HMR، عوض‌کردن تب یا بار سنگین آزمون دیگر نتیجه را مخدوش می‌کند. فایل‌های نتیجه زیر `$WORKSPACE_ROOT/output/behix/` نوشته می‌شوند. `story-failure-check.mjs` سهمیهٔ ذخیره را پیش از ناوبری در context جداگانه محدود می‌کند و برای آزمون شکست صف به مرورگری نیاز دارد که خروجی داستانش از MediaRecorder استفاده کند؛ track بومی ضبط متوقف می‌شود و هیچ recorder ساختگی جای آن قرار نمی‌گیرد.

### فریم مرجع

۱۲ PNG در `tests/story/baselines/` چهار قالب × سه اندازه را پوشش می‌دهند. نسخهٔ مرورگر/فونت، seed و زمان انتخاب در `manifest.json` ثبت است. `story-browser.mjs` baseline گمشده را خطا می‌داند؛ `STORY_VISUAL_CANDIDATES=1` فقط ذخیرهٔ نامزدهای گمشده را مجاز می‌کند. فریم تولیدشده و diff را بازبینی کنید، سپس فقط تصاویر تأییدشده را به baseline منتقل و manifest را به‌روز کنید. تست را دوباره با حالت عادی اجرا کنید. تغییر نسخهٔ مرورگر می‌تواند نیازمند بازبینی مستقل باشد.

### حدود شواهد این محیط

در ۲۰۲۶-۱۰-۱۵، Chromium 140.0.7339.16 رندر و ضبط واقعی را اجرا کرد، اما رمزگذار H.264 آن موجود نبود؛ ویدیوهای آزمون MP4/VP9 بی‌صدا هستند. مسیر رمزگذاری H.264 در Worker تأیید نشده است؛ برابری پیکسل Worker/صفحه بررسی شده است. WebKit دانلودشده GLIBC 2.38 می‌خواهد و میزبان 2.34 دارد؛ اجرای WebKit مسدود است. Safari آیفون واقعی آزمایش نشد.

چهار شکست مجموعهٔ عمومی مربوط به نبود `.grok/skills/og/SKILL.md` و پوشهٔ references است. lint عمومی ۱۵۱ خطا در فایل آمادهٔ `public/mediapipe/vision_wasm_internal.js` دارد. این موارد با تست موفق مسیر داستان یکی نیستند و نباید مخفی شوند.
